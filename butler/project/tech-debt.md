# 技术债登记册

> 最后更新: {date}
> 跨任务持续更新。cr-reviewer 发现代码技术债，auditor 发现系统性技术债，captain 完成后标记状态。

| # | 位置 | 问题 | 风险 | 优先级 | 状态 | 日期 |
|---|------|------|------|:--:|------|------|

## 状态

| 标记 | 含义 |
|------|------|
| 🔴 | 待修复 — 需在下一次迭代处理 |
| 🟡 | 计划中 — 已规划但未排期 |
| 📝 | 登记中 — 已记录待评估 |
| ✅ | 已修复 |
| ⚪ | 已接受 — 评估后决定不修复 |

## 优先级

| 级别 | 标准 |
|:--:|------|
| P0 | 阻塞 — 影响系统稳定性/安全性，必须立即修复 |
| P1 | 高 — 影响可维护性/扩展性，应在本次迭代修复 |
| P2 | 中 — 影响代码质量，可延后 |
| P3 | 低 — 锦上添花 |

## 更新规则

| 触发 | 来源 | 流程 |
|------|------|------|
| 代码审查 | cr-reviewer | 输出 `tech_debt:` YAML（P0+P1 必须） → captain 收集 |
| 系统审计 | auditor | 输出 `tech_debt:` YAML → captain 收集 |
| 任务完成 | captain | 收集所有 tech_debt YAML → 委托 rf-fixer 追加到本表 |
| 任何时候 | 老板 | 直接编辑追加 `[老板原话]` |

## 输出格式（agent 用）

cr-reviewer / auditor 在产出末尾输出以下 YAML 块，captain 会收集并写入：

```yaml
tech_debt:
  - location: "{文件路径或模块}"
    issue: "{一句话问题}"
    risk: "{不修会导致什么}"
    priority: "P0|P1|P2|P3"
    suggestion: "{建议修复方式}"
```
