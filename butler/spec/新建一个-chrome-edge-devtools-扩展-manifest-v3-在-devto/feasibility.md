## 二、可行性判断

**✅ 可执行。**

- 技术路径全部为 Chromium 官方稳定 API（`devtools_page` / `panels.create` / `devtools.network.onRequestFinished` / `navigator.clipboard`），无实验性 API、无平台不可控依赖。
- 纯本地、零依赖、无后端，不涉及数据迁移、兼容旧版本、跨服务协调等高风险项。
- 体积 < 200KB、Chrome/Edge 双兼容在本方案下基本为"免费达标"（原生 JS + 同内核）。

**⚠️ 需澄清但不必停（不阻塞进入后续阶段，建议在任务拆解前裁决）：**

| # | 待裁决项 | 影响的 REQ/AC | 建议默认值 |
|---|---------|--------------|-----------|
| DEC-001 | 面板名称 `Raw Copy` vs `请求复制` | AC-001、REQ-001 | 取 `Raw Copy`（面板标签），界面文案中文 |
| DEC-004 | "仅复制请求/仅复制响应/复制为 cURL"是否纳入 | P2、REQ-013 | 推入 P2 backlog，不做阻断项 |
| DEC-005 | 模式 A（简单格式化）为默认 | AC-015、REQ-018 | 确认默认 A，但 A 只加标题段、**不改 body 一个字符**（见风险 R8） |
| DEC-003 | 大响应阈值默认 10MB | REQ-022、AC-010 | 10MB，常量可配 |
| DEC-002 | HTTP 版本缺失回退 `HTTP/1.1` | REQ-015 | 确认回退文案 |
| DEC-008 | 无选中时点击复制 | 边界 | 按钮置灰 + 提示 |

> 以上均为**范围/文案级**假设，不影响可行性结论；按上述默认执行即可。

## 三、价值评估（VALUE）

**总体 VALUE: `high`**

| 评估项 | 判定 | 依据 |
|--------|------|------|
| 用户痛点强度 | 高 | 原生 Network 面板"复制单条完整请求+响应"极繁琐，需跨标签页分别复制；`Copy as cURL` 无响应体；HAR 导出只能全量/多选且格式复杂（requirement.md §需求背景） |
| 目标用户规模 | 中高 | 前端/测试/后端/技术支持 4 类开发者（US-001~004） |
| 交付即用性 | 高 | 一次操作产出"可直接粘贴给 AI"的纯文本，闭环明确（US-001） |
| 差异化 | 中高 | 现有工具要么缺响应体、要么不保真、要么需装重量级依赖；本方案 = 单条 + 完整请求响应 + 逐字符保真 + 零依赖 |
| 成本收益比 | 高 | 工作量 M（~21 SP），换来高频开发工具；一次开发长期复用 |
| 战略/复用价值 | 中 | 可开源传播；"保真拼接器 + HAR 映射"可沉淀为项目知识 |
| 失败代价 | 低 | 无后端、无数据、无付费；失败不产生线上事故 |

**价值结论:** 高价值、低成本、低失败代价 → 值得投入，建议排入当前迭代。

## 四、风险清单（RISK）

**总体 RISK: `medium`（无高风险项，主要为中低风险 + 可缓解）**

### 4.1 技术风险

| ID | 风险 | 概率 | 影响 | 缓解措施 |
|----|------|:----:|:----:|---------|
| R1 | `onRequestFinished` 对 WebSocket / SSE / 长连接不提供完整响应体；部分请求（预检、缓存命中、失败请求）HAR entry 无 `content.text` | 中 | 中 | **文本类正文缺失 → 必达 `getContent` 兜底取回**（异步 enrich + 原地回填，含 401 等错误响应）；以 `maxBytes` 字节预算 + 并发/队列上限 + 超时兜底控制 R-01 内存放大（2026-10-02 修订）；仅「客观不可获取 / 二进制省略 / 超预算降级」标注 "响应体不可用"；WebSocket 按 A6 仅作资源类型展示；AC 中明确该边界 |
| R2 | **保真约束（AC-007）**：HAR `content.text` 与浏览器实际收到的原始字节可能存在差异（如已按 `content.encoding=base64` 编码的文本响应需解码、gzip 已由 CDP 解码） | 中 | 中 | 严格按 REQ-035 字段映射 + `content.encoding` 判定：仅做必需的 base64→文本解码，不做任何格式化；用逐字符对比测试覆盖 AC-007 |
| R3 | `navigator.clipboard.writeText` 在 DevTools 面板可能因焦点/权限/用户手势受限而拒绝 | 中 | 低 | 已内建降级链：`navigator.clipboard` → `document.execCommand('copy')`（REQ-036）；两者均失败 → 明确提示（REQ-025） |
| R4 | 1000 条 + 实时追加下的列表性能（虚拟滚动实现复杂度） | 中 | 中 | 原生虚拟滚动（DOM 复用）+ 环形缓冲；AC-021 专项验证 |
| R5 | Edge 兼容性差异 | 低 | 低 | 同为 Chromium 内核，API 一致；仅需在 Edge 做一次安装+面板冒烟（AC-018） |
| R6 | 体积 < 200KB | 低 | 低 | 零依赖原生实现，天然达标（AC-017） |

### 4.2 产品 / 范围风险

| ID | 风险 | 概率 | 影响 | 缓解措施 |
|----|------|:----:|:----:|---------|
| R7 | 8 条 `[ASSUMPTION]`（DEC-001~008）未裁决，可能引起返工 | 中 | 中 | 本文件 §二 给出建议默认值；任务拆解前一次性确认 |
| R8 | **语义张力**："模式 A 简单格式化（默认）" 与 "不改动原始响应体 / 不美化 JSON / 不排序字段" 字面上可能冲突 | 中 | 高 | 明确模式 A 仅允许**添加标题段与元信息**，body 部分必须逐字符原样（REQ-018 vs REQ-020）；此点在 AC-007/AC-015 中写死 |
| R9 | "复制成功率 100%"（REQ-034）作为验收指标不可完全保证（受浏览器 API 限制） | 高 | 低 | 将其重述为"存在可用降级路径 + 失败必有提示"，避免不可验收的指标（改写建议，非阻断） |
| R10 | 范围蔓延：P2 附加按钮（仅请求/仅响应/cURL）可能挤占 P0 工期 | 中 | 低 | DEC-004 明确推入 P2 / backlog，不阻塞主验收 |
| R11 | 文档量大（安装/使用/测试用例/隐私/License/图标/打包），可能被视为"杂物"而遗漏 | 中 | 中 | 纳入交付清单逐项验收（AC-019）；文档类 TASK 与代码类分开跟踪 |

### 4.3 安全 / 合规风险

| ID | 风险 | 概率 | 影响 | 缓解措施 |
|----|------|:----:|:----:|---------|
| R12 | 剪贴板内容包含 Authorization/Cookie 等敏感凭证；用户粘贴到第三方 AI 造成凭证外泄（风险在用户侧） | 中 | 中 | 属产品既定用途；在隐私政策与使用说明中显式警示"复制内容可能含敏感信息，请谨慎分享" |
| R13 | 商店上架审核（若需上架 Chrome Web Store）需隐私政策 + 权限说明，存在审核周期 | 中 | 低 | 隐私政策页（DEL-010）已在范围内；上架为可选后续，不阻塞本地 load unpacked 交付 |
| R14 | 权限扩张（误引入 host_permissions/webRequest）破坏"最小权限"承诺 | 低 | 高 | AC-009 硬门禁：manifest 权限清单人工 + 脚本双检查 |

### 4.4 顶级风险（Top 3）

1. **R8 保真语义张力** —— 直接关系核心 AC-007（逐字符一致），是"产品价值主张"的命门，必须在设计阶段定死。
2. **R2 HAR 字段完整性** —— 响应体可能缺失/编码，影响"完整响应"承诺，需边界标注策略。
3. **R7 假设未裁决** —— 8 条假设影响 AC 名称与默认行为，拆解前确认成本最低。

> 折算：1 名熟练实现者约 4–6 个工作日（含文档与打包）。

### 5.2 工作量分布洞察

- **代码量小但"细节敏感"**：真正成本不在写代码，而在 M3 的保真约束（不能多一个空格/换行）与 M2 的虚拟滚动正确性。
- **文档 + 打包占约 1/4**：非技术难点，但需按 AC-019 逐项交付，勿遗漏。
- **无外部依赖 → 无安装/集成成本**，这是本方案工作量可控的关键。
