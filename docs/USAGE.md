# Raw Copy 使用说明

> 适用版本：v1.1.0 ｜ 面板名称：`Raw Copy` ｜ 适用浏览器：最新版 Chrome / Edge（Chromium，Manifest V3）
> 安装步骤见仓库根 `INSTALL.md`。本文覆盖 11 类操作：**打开面板 / 搜索 / 过滤 / 隐藏静态资源 / 清除网络日志 / 选中 / 复制 / 右键菜单复制 / 多选批量复制 / 双击查看明细 / 模式选择（A / B）**。
> 核心承诺：**不美化 JSON、不改动原始响应体**；**单条复制仍为默认与主要场景**，另新增右键、多选批量与双击查看能力。
> 需求覆盖声明（多选批量复制取代原非目标）见第 12 节（**REQ-024 / AC-017**）。

---

## 1. 打开面板

**步骤**
1. 打开你要调试的网页。
2. 按 **F12**，或右键页面 →「检查 / Inspect」，打开 DevTools。
3. 在 DevTools 顶部标签栏（Elements、Console、Network 旁）点击 **`Raw Copy`**。

**预期现象**
- 面板自上而下依次为：**工具栏**（搜索框 + 方法 / 状态码 / 资源类型过滤下拉 + 「隐藏静态资源」开关 + 显示/隐藏计数 + 「清除网络日志」按钮 + 多选工具栏）、**请求列表**（表头：方法 / 域名 / 路径 / 状态 / 类型 / 耗时 / 大小 / 时间）、**底部复制按钮区**（主复制按钮 + 「模式 A」/「模式 B」两个独立按钮 + 「复制为 cURL」）与「隐私政策」入口。
- **默认隐藏静态资源**：首次打开时自动隐藏 `.js` / `.css` / 字体 / 图片 / 媒体 / PDF 等非 API 请求，只留 XHR / Fetch / Document；取消勾选工具栏「隐藏静态资源」即可恢复显示全部（隐藏项仍保留在内存，不会丢失）。
- **清除网络日志**：点击工具栏「清除网络日志」即清空当前列表与缓存，从零重新开始捕获。
- URL 参考 DevTools 拆成「域名 + 路径」两列，长链接不再挤占整行；鼠标悬停域名/路径列可看到完整 URL（复制产物始终是完整 URL）。
- 当前页面暂无请求时，列表区显示空态「暂无网络请求」；在页面中触发请求后，列表**实时自动追加**。
- 内存最多保留最近 **1000** 条请求，超出后自动淘汰最旧的一条。

---

## 2. 搜索

**步骤**
1. 在工具栏最左侧的搜索框输入 **URL 关键字**。

**预期现象**
- 列表实时过滤，只显示 URL 中包含该关键字的请求。
- 无匹配时列表显示「没有匹配的请求」。
- 清空输入框后恢复显示全部请求。

**说明**：搜索针对 URL 做子串匹配。

---

## 3. 过滤（方法 / 状态码 / 资源类型）

**步骤**
1. 使用工具栏的三个下拉框，可任意组合：
   - **方法**：全部 / GET / POST / PUT / DELETE / PATCH / HEAD / OPTIONS；
   - **状态码**：全部 / 2xx / 3xx / 4xx / 5xx；
   - **资源类型**：全部 / XHR / Fetch / Document / Other。（`Script` / `Stylesheet` / `Image` / `Font` / `Media` 等静态资源默认被隐藏，故不出现在下拉中。）

**预期现象**
- 列表实时只显示**同时满足**所有已选条件的请求（多个条件是「且」的关系）。
- 将下拉框选回「全部」即可取消该维度过滤。
- 搜索与过滤可叠加使用。

> 提示：静态资源（`.js` / `.css` / 字体 / 图片 / 媒体 / PDF）默认隐藏，以降低调试 API 时的噪音。需要查看时，取消工具栏「隐藏静态资源」勾选即可恢复显示全部；隐藏只作用于列表与选择，不影响复制内容——复制产物始终包含完整 URL。

---

## 4. 选中

**步骤（两种方式任选）**
- **鼠标**：直接点击列表中的某一行；
- **键盘**：先点击列表区域使其获得焦点，再按 **↑ / ↓** 在请求之间切换选中项。

**预期现象**
- 被选中的行高亮显示。
- 若你选中的那条请求随后因超过 1000 条上限被淘汰，面板会提示「选中的请求已被淘汰」，请重新选择。

---

## 5. 复制（请求 + 响应）

**步骤**
1. 先按第 4 节选中**一条**请求。
2. 点击底部主按钮 **「复制请求 + 响应（原始）」**。
3. 面板底部出现 Toast「已复制到剪贴板」，内容已写入系统剪贴板。
4. 到目标位置（如 AI 对话框）按 **Ctrl+V** 粘贴。

**预期现象与边界**
- **未选中任何请求**时点击复制：提示「请先选中一条请求」，不产生复制动作。
- **大响应**：当响应体超过阈值（默认 10MB）时，会先提示「该响应较大（{大小}），是否继续复制？」，确认后再复制。
- **复制失败**：若剪贴板写入失败，Toast 会显示失败原因。
- **主要入口提示**：右键菜单（第 6 节）是更易达的主要复制入口；底部此按钮保留为**补充**入口，二者产物逐字符一致。

---

## 6. 右键菜单复制

**步骤**
1. 在请求列表的**任意一行**上点击鼠标**右键**。
2. 面板内弹出上下文菜单（命中行**已在多选集合内** → **保留集合**；命中行**在集合外** → 该行被**单选选中**替换集合）。
3. 在菜单中点击主项 **「复制请求 + 响应（原始）」**；若当前选中 **N ≥ 2**，可改点 **「复制选中(N)」** 批量复制。

**预期现象**
- **右键 = 主要、易达入口**：无需先去底部找按钮；右键即弹出菜单。
- 菜单主项为 **「复制请求 + 响应（原始）」**，其剪贴板产物与底部同名按钮**逐字符一致**（固定模式 A）。
- **多选态右键不丢选择**：若右键的行**已在当前多选集合内**，集合保持不变，菜单会追加 **「复制选中(N)」**；若右键的行**在集合外**，则按**单选替换**（保留「右键定位该行」的习惯）。
- 当当前选中条数 **N ≥ 2** 时，菜单顶部会追加 **「复制选中(N)」** 项（与第 7 节工具栏按钮等价，产物逐字符一致）。
- **关闭菜单**：按 `Esc`、点击菜单以外的区域、滚动请求列表、或 DevTools 窗口失焦，菜单都会自动关闭。
- 在表头或列表空白处右键**不会**弹出菜单（仅对请求行生效）。

> 实现说明：菜单为**面板内自绘**，**未申请** `contextMenus` 浏览器权限，权限清单仍仅 `clipboardWrite`。

## 7. 多选批量复制

**多选交互**

| 操作 | 效果 |
|------|------|
| **单击** | 单选替换（保持原有单选语义） |
| **Ctrl / Cmd + 点击** | 切换该行是否在选中集合内（可逐个增删） |
| **Shift + 点击** | 以上一次锚点为起点、按当前**可见列表顺序**做范围选择（**替换**集合） |
| **Ctrl / Cmd + Shift + 点击** | **并集扩选**：在既有集合基础上追加锚点区间，**不清空**先前已选项 |
| **↑ / ↓** | 单选移动（会清空多选集合，回落为单选） |

**批量入口**
- 工具栏 **「全选」**：选中当前**过滤后可见**的全部行。
- 工具栏 **「复制选中(N)」**：按钮文本实时显示当前选中条数 `N`（`N=0` 时为禁用态）；点击即批量复制（**批量入口固定按默认模式 A**）。
- 「复制选中(N)」也出现在右键菜单中（当 `N ≥ 2` 时），与工具栏按钮等价。

**输出结构**
- 当 **N ≥ 2**：输出为 **N 段**，段与段之间以清晰的序号分隔行 `===== #i/N =====`（`i` 从 1 到 N，按**可见列表顺序**排列）。每一段仍是该条请求的「请求 + 响应」**原始纯文本**（批量入口固定按默认**模式 A**），多条之间**不会混淆**、不会跨条错误拼接。
- 当 **N = 1**：输出与单条复制**逐字符一致**（**不加**序号 / 分隔行）。
- **范围基准**：`N` 的统计与「全选」均以**当前过滤后可见列表**为准（被过滤隐藏的行不计入）。

**大响应**：若本批中**任一条**响应体超阈值，会弹出**一次**确认框（含超限条数与最大体积）；取消则整批不复制。

**批量输出示例（节选）**

```text
===== #1/3 =====
===== REQUEST =====
GET https://cdn.example.com/img.png HTTP/2

===== RESPONSE =====
HTTP/2 200 OK
Content-Type: image/png

[Response Body]
[Base64 content omitted: length 96]

===== #2/3 =====
...（第 2 条请求 + 响应原文）...

===== #3/3 =====
...（第 3 条请求 + 响应原文）...
```

## 8. 双击查看明细

**步骤**
1. 在请求列表的任意一行上**双击**。

**预期现象**
- 打开一个**覆盖式抽屉（overlay drawer）**，展示该请求的完整**六要素原文**：
  1. 请求方法 + URL
  2. 请求头
  3. 请求体
  4. 响应状态码 + 状态文本
  5. 响应头
  6. 响应体
- 明细内容为**原始文本**（与复制口径一致：不美化 JSON、不改动响应体、请求 / 响应头保持原始顺序）；明细展示**始终为原始文本**，不随「模式 A / 模式 B」按钮的选择而变化（模式只影响「复制」产物）。
- **单击仍为「选中」，只有双击才打开明细**（避免与选中 / 多选冲突）。双击打开明细**不会改动**当前的多选集合。
- **关闭并返回列表**：点击抽屉的**关闭按钮**、按 `Esc`、或点击抽屉**遮罩**均可关闭。
- 明细抽屉内提供 **「复制请求 + 响应（原始）」** 按钮，其产物与主复制按钮一致。
- 若打开中的记录随后被淘汰（超过 1000 条上限），明细会**自动关闭**并提示「该请求已被淘汰，明细已关闭」。

## 9. 复制模式 A / B（两个独立按钮）

底部复制按钮区提供**两个独立按钮**：**「模式 A」**与**「模式 B」**。点击哪个按钮，就按哪个模式复制**当前选中**的请求（**动作即模式**，不再有「先切换再复制」的开关）。

| 模式 | 名称 | 输出结构 | 默认 |
|:----:|------|---------|:----:|
| **A** | 简单格式化 | 增加标题段与段标签，正文逐字符原样 | ✅ 默认（主复制按钮与批量入口均按 A） |
| **B** | 纯原始 | 不加任何标题，直接拼接请求块与响应块 | — |

**使用步骤**：先选中一条请求，然后直接点击 **「模式 A」** 或 **「模式 B」**；无需任何预先切换。

> 「模式 A」「模式 B」按钮的 `title` 提示分别为「加标题段与段标签，正文逐字符原样」「不加任何标题，直接拼接」。按钮面板内不显示切换状态，复制模式由**这一次点击**决定。

**模式 A 输出结构（示意）**

```text
===== META =====
开始时间: 2026-10-02T10:00:00.000Z
总耗时: 123 ms
资源类型: XHR
MIME 类型: application/json

===== REQUEST =====
POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json

[Request Body]
{"username":"a","password":"b"}

===== RESPONSE =====
HTTP/1.1 200 OK
Content-Type: application/json

[Response Body]
{"code":0,"message":"success","token":"xyz789"}
```

**模式 B 输出结构（示意）**：与上例相同的请求块与响应块，但**没有** `===== META =====`、`===== REQUEST =====`、`===== RESPONSE =====` 标题，也**没有** `[Request Body]` / `[Response Body]` 段标签，两段之间以一个空行分隔。

### 保真特性（两种模式一致）

- **不美化 JSON**：不缩进、不重排换行、不排序字段、不压缩，也**不**添加 Markdown 代码块。
- **不改动原始响应体**：响应体**逐字符原样**复制。模式 A 只新增标题段 / 段标签，**绝不修改正文任何一个字符**；模式 B 不做任何新增。
- **单条复制不含其他请求**：单条复制路径绝不附带列表中的其他请求（多选批量复制为**独立入口**，见第 7 节与第 12 节「需求覆盖声明」）。
- **保序**：请求头 / 响应头按**原始顺序**输出，每行 `Name: Value`。
- **请求部分**包含：请求方法、完整 URL、HTTP 版本（无法获取时回退 `HTTP/1.1`）、请求头、请求体（有则输出）。
- **响应部分**包含：状态码、状态文本、响应头、响应体。
- **元信息**（开始时间 / 总耗时 / 资源类型 / MIME 类型）只出现在**标题段**，不插入正文。
- **非文本内容**：
  - 二进制响应标注 `[Binary content omitted: <mime>, <bytes> bytes]`；
  - Base64 且为文本类 MIME 时尝试按 UTF-8 解码，否则标注 `[Base64 content omitted: length N]`。

## 10. 底部其它按钮

面板底部除主复制按钮（**「复制请求 + 响应（原始）」**，固定模式 A）与 **「模式 A」/「模式 B」** 两个模式按钮外，还有：

- **复制为 cURL**：将请求转换为 cURL 命令（可选按钮，**当前版本可能尚未启用**）。

> v1.1.0 起，原「仅复制请求」「仅复制响应」分段复制能力已**移除**（菜单项与按钮均不再提供）。主流程请使用「复制请求 + 响应（原始）」或模式 A / B 按钮。

---

## 11. 粘贴使用

复制完成后，示例请求 `{"code":0,"message":"success","token":"xyz789"}` 会以**原始单行文本**粘贴到 AI 对话框，AI 可读取完整请求与响应，而不会因为多行美化被打断。

## 12. 需求覆盖声明（REQ-024 / AC-017）

本版本（v1.1.0）相对原始需求文档 `req.txt` 有**一处显式的非目标覆盖**，特此记录：

- `req.txt` 原非目标曾包含：**「不复制全部请求」** 与 **「只复制当前选中的那一条请求，绝不附带其他请求」**。
- 本增强**明确取代（覆盖）**上述两条非目标：用户现可主动使用 **「多选批量复制」**（第 7 节），一次复制多条请求，输出为 N 段并以 `===== #i/N =====` 分隔。
- **单条复制仍为默认与主要场景**，且其输出格式**逐字符不变**（冻结契约，AC-007）；多选批量复制仅在用户**显式**选中多条并点击「复制选中(N)」时才发生，不会影响单条复制的既有行为。
- **其余原始非目标继续有效**：不上传数据到任何服务器、不自动发送给 AI、不做 JSON 美化 / 压缩 / 排序 / 语法高亮、不修改 / 拦截 / 阻断任何网络请求、不收集用户数据 / 埋点 / 遥测、不请求与功能无关的敏感权限。

> 对应条目：**REQ-024**（需求）、**AC-017**（验收标准）、**DEL-008**（交付物）。

## 13. 隐私与数据安全

- **仅在内存**：所有捕获的请求数据只存在于 DevTools 内存中；**关闭 DevTools 即销毁**。
- **不收集 / 不存储 / 不传输**：无 localStorage / IndexedDB / chrome.storage 写入；无服务器、无分析、无遥测、无广告。
- **不发起网络请求**：扩展自身零网络行为；不修改、不拦截、不阻断被调试页面的请求。
- **权限最小**：仅申请 `clipboardWrite`（写入剪贴板）；右键菜单为面板内自绘，未新增任何浏览器权限。
- **敏感信息警示**：复制内容可能包含 **Authorization、Cookie、token** 等敏感凭证。扩展本身**不会外传**，但当你把复制内容粘贴到第三方服务（如在线 AI）时，请自行确认这符合你所在环境的合规要求。
- **批量复制敏感凭证警示**：使用 **「复制选中(N)」批量复制**时，一次可能把**多份** `Authorization` / `Cookie` / token 等敏感凭证写入剪贴板。**单条** 与**批量** 都不会由扩展外传，但把批量内容粘贴到第三方前，请务必确认这多份凭证的合规性。

## 14. 常见边界行为

| 场景 | 表现 |
|------|------|
| 无请求体（GET / HEAD） | 不输出请求体段 |
| 空响应体（204 / 304 / HEAD） | 不输出响应体，或按「响应体不可用」标注 |
| 失败请求（状态码 0 / 被取消 / 被阻断） | 列表正常显示，复制时按当前可用字段输出 |
| 请求数达到 1001 条 | 淘汰最旧一条，列表与缓存始终维持最多 1000 条 |
| 打开多个被检查页面 | 只捕获 DevTools **当前所检查 target** 的请求 |
| 多选集合中含被淘汰记录 | 该记录 id 自动从选中集合移除，计数 `N` 实时更新 |
| 打开中的明细记录被淘汰 | 明细自动关闭并提示「该请求已被淘汰，明细已关闭」 |
| 过滤条件变化 | 仍可见的选中项保留，不可见项从集合剔除（`N` 随之更新） |
| 静态资源默认隐藏 | `.js` / `.css` / 字体 / 图片 / 媒体 / PDF 不出现在列表与资源类型下拉；取消「隐藏静态资源」勾选即恢复显示全部（数据仍在内存） |
| 清除网络日志 | 清空全部已捕获请求、选中与计数；页面重新产生请求后列表重新追加 |
